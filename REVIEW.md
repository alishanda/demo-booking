# Code review: `BookingController`

Разбор исходного кода в `app/Http/Controllers/BookingController.php` до доработки.

## `store`

### 1. SQL-инъекция через конкатенацию в сыром SQL
**Серьёзность:** critical

```php
DB::select("SELECT id FROM bookings
    WHERE room_id = {$request->room_id}
    AND starts_at <= '{$request->ends_at}'
    AND ends_at >= '{$request->starts_at}'");
```

Параметры запроса подставляются в строку без биндингов. Любой клиент может выполнить произвольный SQL.

**Как исправить:** Eloquent / Query Builder с плейсхолдерами, либо `DB::select` с bindings.

### 2. Неверная проверка пересечений (встречи «впритык» считаются конфликтом)
**Серьёзность:** critical

Условие `starts_at <= ends_at AND ends_at >= starts_at` считает пересечением пары `10:00–11:00` и `11:00–12:00`. По правилам задания соседние слоты разрешены.

**Как исправить:** полуинтервал `[starts_at, ends_at)` — конфликт только если `starts_at < new_ends_at AND ends_at > new_starts_at`.

### 3. Клиент может подставить чужой `user_id`
**Серьёзность:** critical

`Booking::create($request->all())` принимает `user_id` из тела запроса. Автор брони не обязан совпадать с аутентифицированным пользователем.

**Как исправить:** брать `user_id` только из `$request->user()`, не из input; не включать `user_id` в Form Request / fillable для массового присвоения из запроса.

### 4. Нет валидации входных данных
**Серьёзность:** major

Нет проверки существования комнаты, формата дат, обязательности полей, `ends_at > starts_at`. Ошибки БД / Carbon вместо понятного 422.

**Как исправить:** Form Request + понятные сообщения валидации.

### 5. Рабочее время проверяется неверно
**Серьёзность:** major

- Смотрится только час начала (`$start->hour`), конец брони не проверяется.
- Время парсится в таймзоне приложения / смещении клиента, а не офиса комнаты (`Europe/Moscow` / `Asia/Novosibirsk`).
- Бронь `19:30–20:30` или целиком за пределами дня офиса может пройти / отсечься ошибочно.

**Как исправить:** конвертировать `starts_at`/`ends_at` в timezone офиса комнаты и требовать `start >= 09:00` и `end <= 20:00` в этот локальный день.

### 6. Нет правил длительности и сетки 15 минут
**Серьёзность:** major

Нет ограничений «от 15 минут до 4 часов» и шага 15 минут для начала/конца.

**Как исправить:** проверять длительность и выравнивание минут (и секунд = 0) на сетку 15 минут; при нарушении — 422.

### 7. Гонка при одновременных запросах на один слот
**Серьёзность:** major (бонус задания)

Проверка конфликта и `create` не атомарны: два параллельных запроса могут оба не найти пересечение и создать двойную бронь.

**Как исправить:** транзакция + `lockForUpdate` на комнату (или строку) перед проверкой; надёжнее на уровне БД — exclusion constraint на `tsrange` по `room_id`.

### 8. Конфликт отдаётся как 409 с плоским `error`
**Серьёзность:** minor

Задание требует понятные ошибки валидации (422). Сейчас формат ответа отличается от стандартного Laravel validation JSON.

**Как исправить:** `ValidationException` / ошибки по полям в формате 422.

## `destroy`

### 9. Отменить бронь может любой аутентифицированный пользователь
**Серьёзность:** critical

Нет проверки, что `$request->user()->id === $booking->user_id`.

**Как исправить:** проверять авторство; иначе 403.

### 10. Нет Form Request / явной авторизации
**Серьёзность:** minor

Логика «только автор» размазана бы по контроллеру; удобнее Policy или метод сервиса.

**Как исправить:** `BookingPolicy` или сервис отмены с явной проверкой владельца.

---

## `index` (только ревью, не чиним)

### 11. `orderByRaw('starts_at DESC')`
**Серьёзность:** не проблема (выглядит подозрительно)

Строка захардкожена, инъекции нет. Но `orderByRaw` здесь избыточен.

**Как улучшить (по желанию):** `orderByDesc('starts_at')` — яснее и безопаснее по привычке.

### 12. Пагинация без Resource
**Серьёзность:** minor / не баг

Отдаётся сырая модель. Для текущего задания достаточно; для API лучше Eloquent API Resource.

---

## `today` (только ревью, не чиним)

### 13. `whereDate('starts_at', today())` в таймзоне приложения
**Серьёзность:** major

`today()` берёт календарный день app/UTC, а не офиса комнаты. Для Новосибирска «сегодня» может отличаться от Москвы/UTC — список броней на день будет неверным.

**Как исправить:** считать «сегодня» в `$room->office->timezone` и фильтровать интервалом `[startOfDay, endOfDay]` в UTC/хранении.

### 14. N+1 по `user`
**Серьёзность:** major

В `map` вызывается `$b->user->name` без `with('user')`.

**Как исправить:** `->with('user')` до `get()`.

### 15. Склейка Carbon в строку
**Серьёзность:** minor

`$b->starts_at . ' – ' . $b->ends_at` зависит от `__toString` / формата каста; лучше явный `toIso8601String()` и, при необходимости, время в TZ офиса.

### 16. Нет проверки авторизации сверх Sanctum
**Серьёзность:** не проблема для текущего ТЗ

Эндпоинт закрыт `auth:sanctum`; отдельной политики на комнату в задании нет.

### 17. Логирование без полезного контекста
**Серьёзность:** minor

`Log::withContext(['booking_id' => ...])` + сообщение `Booking created` — контекст не попадает в запись канала так, как ожидается без передачи в сам `info`, и не логируются room/user/интервал.

**Как исправить:** передавать массив контекста вторым аргументом в `info()`.
